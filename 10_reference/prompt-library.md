# 常用提示詞庫

整理依據：00_inbox/raw-idea.md
建立日期：2026-08-25

使用方式：每次開始任務時，直接複製對應的提示詞，貼入 Claude 對話框，視需要填入【】內的內容。

---

## 一、開場提示詞（每次開新任務前使用）

```
Before starting a new mission, 請先閱讀 README.md 和 CLAUDE.md。

我要在這個工作資料夾中開始一個新任務。

任務名稱：【填寫任務名稱】
任務目標：【填寫希望產出的成果】
可讀取材料：【列出材料位置】
成果應放位置：【例如 30_output/xxx.md】
禁止操作：【例如不要修改原文件、不要刪除、不要讀資料夾外文件】

請先回答：

1. 你會讀取哪些文件

2. 你會產出什麼文件

3. 你是否需要修改任何原文件

4. 你建議的執行步驟

5. 哪些地方需要我先確認

在我確認前，不要新增、修改、刪除任何文件。
```

## 二、社群內容想法

### 2-1 發想貼文主題

```
我想為【品牌名稱 / 帳號名稱】發想社群貼文主題。
目標受眾：【描述目標受眾】
平台：【Instagram / LinkedIn / Facebook】
本週主軸：【輸入本週主題或活動】

請提供 5 個貼文方向，每個方向包含：標題、內容重點、適合搭配的視覺風格。
請先列出方向供我確認，確認後再展開內容。
```

```
我有一個內容想法，請幫我整理成貼文草稿。

想法：【貼上你的原始想法】
語氣：【專業 / 輕鬆 / 教育性】
字數限制：【300字以內 / 無限制】

請先給我一個草稿版本，我確認方向後再修改。
成果請說明放在哪裡。
```

## 三、課程筆記整理

### 3-1 整理逐字稿或原始筆記

```
我有一份課程筆記，請幫我整理成結構化格式。

文件位置：20_active/【文件名稱】
整理方式：
- 保留原始文字，不要改寫意思
- 加上標題層級
- 列出重點摘要（不超過 5 點）
- 列出行動項目（如有）

請先說明整理計劃，等我確認後再執行。
不要修改原始文件，成果放到 30_output/。
```

### 3-2 從筆記提取可用素材

```
請從這份筆記中提取可以再利用的素材：
文件位置：10_reference/【文件名稱】

提取重點：
- 可以用於社群貼文的金句或觀點
- 可以用於培訓材料的框架或案例
- 需要進一步研究的問題

請只做提取，不要修改原始文件。
```

## 四、文件整理流程

### 4-1 資料夾體檢

```
請做資料夾體檢，不要新增、修改、刪除任何文件。
請依序閱讀 README.md、CLAUDE.md，以及 00_inbox/ 資料夾內的文件。
請回答：
1. 00_inbox 裡目前有哪些文件？
2. 每份文件應該屬於哪個子資料夾？
3. 有沒有不應該放在這裡的文件？
請只做分析，等我確認後再提出整理計劃。
```

### 4-2 整理 00_inbox

```
請幫我整理 00_inbox/ 資料夾。
整理規則請參考 README.md 的資料夾分區說明。

請先列出每份文件的建議去處，等我確認後再移動。
不要刪除任何文件。
```

### 4-3 歸檔已完成任務

```
任務【任務名稱】已完成。
請幫我確認：
- 成果是否已放在 30_output/？
- 原始材料是否還在原位？
- 可以移入 90_archive/ 的文件有哪些？

請先列出清單供我確認，確認後再執行移動。
```

## 五、安全檢查提示詞

```
在開始這個任務之前，請先確認：
1. 我提供的文件是否包含密碼、API Key、客戶私密資料、或公司機密文件？
2. 如果有，請告訴我哪份文件有疑慮，不要繼續處理。
3. 如果沒有，請繼續說明你的處理計劃。
```

## 六、任務結束回報格式

```
請對本次任務做收尾回報，不要再修改文件。

請列出：

1. 你讀取了哪些文件

2. 你新增了哪些文件

3. 你修改了哪些文件

4. 你沒有處理但建議我後續處理的材料

5. 哪些成果已放到 30_output

6. 哪些材料建議移到 90_archive

7. 是否有需要補進 CLAUDE.md 的新規則
```

## 十一、CLAUDE.md 規則提煉（任務問題反推）

```
剛才這次任務出現了一個需要反覆避免的問題：
【描述問題】

請根據這個問題，幫我寫 1-3 條可以補進 CLAUDE.md 的規則。

要求：
- 規則要短、具體、可執行
- 不要寫成空泛口號
- 不要加入和本問題無關的內容
- 請說明每條規則應該放在 CLAUDE.md 的哪個區塊

請只提供建議，不要直接修改文件。
```

## 八、個人品牌

```
## 輸出格式與語氣

語氣清楚、直接、接地氣，不要過度官話。
如果生成社群內容，請包含：Hook、正文、CTA、可替換版本。
不要承諾無法證明的結果。
如果資料不足，標記「待確認」。
```

## 九、課程製作

```
## 課程內容規則

每節 lesson 必須聚焦一個具體問題。
請用非技術學員能理解的語言解釋概念。
請包含可跟做步驟、可複製提示詞、常見卡點、建議執行項和自測學習清單。
不要把內部製作信息寫進學員正文。
```

## 十、客戶交付

```
## 客戶交付安全規則

只處理已授權材料。
不要生成未經確認的承諾、價格、合約條款或保證結果。
涉及客戶私密資料時，先詢問是否可以處理。
所有交付內容都要標記需要人工確認的地方。
```
